## Owner recovery for the reported incident

1. Review/deploy the platform changes through the normal Compose build. Retain every data/key/control/executor volume and immutable runtime pin; do not edit the PDF Tools source/catalog or lockfiles to grant permissions.
2. Read the incident's actual current stage, original policy/deadline, source revision, pending/unknown operations and provider accounting. Reconcile any uncertain mutating operation first. This report does not infer the current values from the incident's original approximate tool count.
3. If original capacity is exhausted, use a separate explicit owner limit decision; dependency approval cannot extend it. If capacity remains and the owner explicitly resumes/retries, a saved tool-free blocked model outcome stays preserved/charged while a new bounded assessment can use RequestDependencyApproval. Completed BA/architecture checkpoints are reused where valid.
4. In project Dependencies or global Approvals, inspect exact versions/reasons/unknowns. Separately consent to bounded official registry resolution. Review complete direct/transitive origins, integrity, aliases, license declarations and unknown security findings. Approve only reviewed packages; no executable grant exists until the complete graph is approved. Reject/Request Changes is a durable decision, not chat.
5. Explicitly resume the same run. The engineer calls PrepareApprovedDependencies before modifying manifests/locks. Source drift, integrity failures or unsupported adapters remain blocked; inspect the preserved proposal and actual workspace rather than overwriting files. On an uncertain acquisition, reconcile its receipt or explicitly authorize a checked source-free retry. Do not replay an uncertain source mutation.
6. Require actual tests for the final source revision, QA, real diff review and the existing delivery approval before a draft PR. Never automatically merge or create another customer execution to conceal a failed outcome.

Known limits are explicit in [ADR 017](architecture/017-dependency-governance.md): npm public registry only, exact versions, fixed preparation paths/resource ceilings, scripts disabled, no vulnerability/signature certification or cross-run grant inheritance. This is not certified support for every language/package ecosystem. Screenshots and final verification identities accompany the phase PR.
