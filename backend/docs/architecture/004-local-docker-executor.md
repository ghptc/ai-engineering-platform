# ADR 004: Local Docker executor over an authenticated Unix socket

Status: accepted for Milestone 8. Supersedes the cloud-executor prerequisite in ADR 003; its execution trust boundary remains mandatory.

The owner runs the platform exclusively on an Arch Linux workstation. The ASP.NET Core/React deployment remains one application container, MongoDB remains separate, and a host .NET daemon performs controlled Git/file operations and starts ephemeral Docker workloads. The application container receives only the executor Unix socket directory and a high-entropy control token. It never receives the Docker socket. No TCP listener is created by the daemon.

The daemon has a dedicated, owner-controlled repository/installation/default-branch allowlist and fixed command profiles. It serializes workspace operations, records monotonically increasing fences and lease owners, rejects changed arguments for an existing operation ID, persists receipts atomically, and resumes them after restart. Source snapshots are hashed independently of Git metadata. A successful test profile records the tested revision; commit/push require that unchanged revision. Only `engineering/<runId>` may be committed/pushed. Protected default branches are never push targets.

Build/test execution uses an administrator-built image pinned by immutable image ID. The daemon verifies Linux, cgroup v2, resource controllers and default seccomp support, creates a container with fixed isolation flags, inspects its configuration before starting, and records the container's actual exit status afterward. It rejects unexpected privileges, host namespaces, mounts, resources or network settings. The container runs as UID/GID 65532, with all capabilities dropped, no-new-privileges, a read-only root, private IPC/cgroup namespaces, network=none, a PID limit, CPU/memory/swap limits and two bounded tmpfs mounts. `/workspace` permits executable test binaries; `/tmp` does not. Source arrives as a regular-file-only tar stream through stdin; no host directory, Docker socket, `.git`, owner home or application secret is mounted. Generated outputs stay in tmpfs and are destroyed after each workload. Only validated file tools change canonical source.

The trusted entrypoint validates archives before starting the fixed command argument array. The model can select a registered profile, not shell text, an image, mount, network or environment. Dependencies must exist in an approved offline-cache image; missing packages fail closed. Explicit owner tooling can copy selected dependency cache data into an image, without mounting the owner's home or running repository lifecycle scripts on the host. GitHub HTTPS clone/push and GitHub App token exchange occur only in the trusted transfer plane. Short-lived tokens are provided to Git through a scrubbed environment, never arguments or workload containers. Git ignores system/global configuration and disables hooks, fsmonitor, credential helpers, external protocols and arbitrary filters; Git subprocesses have time/output/address-space/per-file limits.

Workload cleanup uses an independent cancellation token. Cleanup failures latch the executor unhealthy. At startup it removes only abandoned containers carrying its state-directory ownership label, then prunes expired canonical workspaces. The state directory is private, only one daemon holds its ownership lock, and the systemd unit isolates it from owner home directories. The Docker control plane remains a privileged trust boundary: use the dedicated service identity, protect its config/token/state, and prefer a rootless engine with delegated cgroup v2 where available. Containers share the host kernel; this is not a microVM boundary.

The remote HTTPS adapter remains available, but local operation requires no cloud executor. HTTP is allowed only inside the explicitly constructed Unix-socket transport, never through a configurable plaintext network endpoint. The UI reports configured versus verified-ready state, execution cost/budget, iteration limits, retries, duration and tool-call limits.

Validation uses disposable local bare repositories with real Git clone/patch/commit/push, real .NET/Node test processes, real Unix-socket authentication, restart/idempotency and Docker isolation/timeout/output/cleanup checks. The production daemon rejects test file remotes; they require the Testing environment and a fixture path under the test state root. Optional live-agent tests additionally require an explicit `aep-sandbox-*` GitHub repository and bounded model prices/budget. They never use the platform's protected default branch.

References: [Docker runtime constraints](https://docs.docker.com/engine/containers/run/), [Docker tmpfs semantics](https://docs.docker.com/engine/storage/tmpfs/), [OpenAI function/tool calling](https://developers.openai.com/api/docs/guides/function-calling). This implementation retains the existing schema-driven operational tool loop and validates tool results independently of model claims.
